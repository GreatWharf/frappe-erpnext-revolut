# Security and access

[All guides](README.md)

## Permissions

- **System Managers:** configure connections, import extra data and review source records.
- **Accounting users:** use standard Bank Transactions with ERPNext’s normal permissions.
- Each connection belongs to one Company. Use separate sites for mutually untrusted businesses.
- The app requests **READ access** to Revolut. It cannot send payments or exchange money.

## Credentials and files

- Private keys and tokens are encrypted using Frappe’s site encryption key.
- The browser setup shows the public certificate; the private key stays on the server.
- Receipt attachments are private and follow the expense document’s permissions.
- Back up the **database, site files and encryption key** together.
- Keep tokens, private keys and returned authorization URLs out of GitHub issues, screenshots and logs.

## Maintenance

- Use HTTPS and keep the server clock accurate.
- Renew certificates before expiry. Certificates generated by the app last one year.
- Reauthorize the existing connection when consent expires or is revoked.
- Before removing the app, revoke its access and any webhook registration in Revolut. Uninstalling ERPNext code does not revoke remote access.
